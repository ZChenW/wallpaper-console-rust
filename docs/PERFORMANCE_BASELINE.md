# Performance Baseline

Current scope: Tauri 2 GUI + Rust CLI. Wails measurements are historical and are not used for current performance decisions.

Date: 2026-06-11

## Environment

- OS: Arch Linux
- Shell-run benchmark mode: Rust CLI `library-page-json` calls; after SQL helper extraction this exercises the same `wc-storage` SQLite page helper used by Tauri.
- GUI binary path: `target/release/wallpaper-console-tauri` before install, `wallpaper-console-gui-rust` after install
- Storage files: temporary `$XDG_CONFIG_HOME/wallpaper-console`, generated by `scripts/benchmark_library.sh`

## Repeatable Library Benchmark

```bash
# Default: 1k and 10k rows
./scripts/benchmark_library.sh

# Include 50k rows
SIZES="1000 10000 50000" ./scripts/benchmark_library.sh

# Use release CLI after `cargo build --release -p wc-cli`
WCR_BIN=target/release/wallpaper-console-rust SIZES="1000 10000 50000" ./scripts/benchmark_library.sh
```

The script generates both `library.tsv` and `wallpapers.db`, then measures:

- first page: newest sort, offset 0, limit 120
- later page: newest sort, offset 480, limit 120
- search: filename search with name sort

CLI `rescan` now streams discovered candidates through metadata probing, temporary
TSV output, and SQLite staging batches. This keeps the hot path bounded by the
current batch size instead of retaining the full path and entry vectors before
SQLite replacement. The final SQLite commit remains atomic: failures during
staging or commit preserve the previous library and remove the temporary TSV.

| 1,000 | TSV | search | 4 | 100 | 100 |
| 1,000 | SQLite | first_page | 5 | 1,000 | 120 |
| 1,000 | SQLite | page_5 | 5 | 1,000 | 120 |
| 1,000 | SQLite | search | 4 | 100 | 100 |
| 10,000 | TSV | first_page | 7 | 10,000 | 120 |

| 10,000 | SQLite | first_page | 6 | 10,000 | 120 |
| 10,000 | SQLite | page_5 | 6 | 10,000 | 120 |

| 50,000 | TSV | first_page | 23 | 50,000 | 120 |

Interpretation: SQLite is the preferred large-library GUI backend for paged browsing. TSV remains compatible and usable, but it does more bounded in-process work per page and grows more noticeably at 50k rows.

Tauri command latency is not identical to CLI process latency. For GUI-specific timing, use the frontend performance overlay (`library.page.ms`) or add a Tauri command harness before comparing WebView behavior.

## Manual GUI Profiling

```bash
./install.sh --build-only
WALLPAPER_CONSOLE_GUI_RUST=target/release/wallpaper-console-tauri ./scripts/profile_gui.sh 45 \
  | tee /tmp/wallpaper-console-gui-baseline.csv
```

During manual GUI profiling, check:

- first library render time
- scroll smoothness with 1k, 10k, and 50k generated rows
- thumbnail queue depth and hit/miss counters using `localStorage.setItem('wcPerfOverlay', '1')`
- view-switch animation responsiveness
- scan progress/cancel feedback

## Thumbnail Generation

Use a real wallpaper directory because synthetic TSV rows do not exercise image/video decoders:

```bash
XDG_CONFIG_HOME="$(mktemp -d)" wallpaper-console-rust add /path/to/wallpapers
XDG_CONFIG_HOME="$XDG_CONFIG_HOME" wallpaper-console-rust rescan
WALLPAPER_CONSOLE_GUI_RUST=target/release/wallpaper-console-tauri ./scripts/profile_gui.sh 45
```

## SQLite FTS Search

Date: 2026-06-15

SQLite search now uses an FTS5 index over path, title, workshop_id, and project_type.
Empty-search paging still uses the regular ordered indexes.
Schema creation records the current FTS schema version and rebuilds the index
when that version changes; `sqlite-verify` also checks FTS/content integrity so
stale search indexes fail verification instead of silently degrading GUI search.

Record:

- number of image, GIF, and video files
- whether `ffmpeg`, `ffmpegthumbnailer`, and ImageMagick are installed
- thumbnail cache entries, total size, and failure count from Settings
- any visible stutter or repeated failed thumbnail attempts
